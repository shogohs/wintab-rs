# 診断ガイド

通常の利用で診断コマンドを実行する必要はありません。権限やウィンドウ取得を調べる場合に、アプリ内実行ファイルをターミナルから起動します。

```sh
APP="/Applications/wintab-rs.app/Contents/MacOS/wintab-rs"
"$APP" --status
```

診断コマンドを実行すると、現在のアクセシビリティと入力監視の許可状態が表示されます。アクセシビリティ権限の要求は非同期のため、要求直後に未許可と表示されても拒否が確定したわけではありません。

## 権限の確認

「システム設定」>「プライバシーとセキュリティ」で「アクセシビリティ」と「入力監視」を確認してください。許可後、常駐アプリではメニューバーの `WT` >「権限状態を再確認」を選びます。

すでに許可済みなのに未許可と表示される場合は、設定に登録されたアプリと、現在起動している `.app` の場所が一致しているかを確認してください。ビルドの差し替えでad-hoc署名や起動場所が変わった場合は、設定からアプリを一度削除して再登録すると改善することがあります。

## コマンド一覧

各コマンドの秒数は0より大きく10以下です。`PID` は対象アプリのプロセスIDです。

```sh
"$APP" --pid PID
"$APP" --tap-seconds 5
"$APP" --capture-seconds 5
"$APP" --list-windows PID
"$APP" --raise-window PID INDEX
"$APP" --switch-pid PID --seconds 10
"$APP" --list-candidates
"$APP" --switch --seconds 10
```

- `--pid` はAccessibility APIが返す指定アプリのウィンドウ数を表示します。
- `--tap-seconds` は指定時間、Command+Tab相当のキー押下数を数えます。入力はそのまま通過し、キー内容やタイトルを保存しません。
- `--capture-seconds` は指定時間だけCommand+Tabを抑止する入力診断です。回数を記録しますが、ウィンドウは切り替えません。
- `--list-windows` は指定アプリのウィンドウ番号とタイトルを表示します。
- `--raise-window` は指定した番号のウィンドウを前面に出すよう試み、AXフォーカス状態を表示します。
- `--switch-pid` は指定アプリの候補から1セッションだけ選ぶ診断モードです。
- `--list-candidates` は複数アプリから切り替え候補を取得します。
- `--switch` は候補から1セッションだけ選ぶ診断モードです。

### 入力診断

`--tap-seconds` はlisten-onlyで動作し、入力を変更・抑止しません。Input Monitoringが許可済みでも、イベントタップの作成に失敗する場合があります。その失敗だけで権限不足とは判断できません。

`--capture-seconds`、`--switch-pid`、`--switch` は診断用の短時間モードです。Command+Tabの入力を一時的に処理しますが、常駐アプリの通常操作と同じ機能範囲を保証するものではありません。期限切れや入力監視の停止時は切り替えを行わず終了します。

### ウィンドウ取得・前面化

`--list-windows PID` の番号はその時点のAccessibilityウィンドウ配列内の位置で、固定IDではありません。ウィンドウを前面化すると配列順が変わることがあるため、番号を再利用する前に一覧を取り直してください。

`--raise-window` の成功やAXフォーカス属性の一致だけでは、実際にキー入力を受け取ることやSpaceの移動までは確認できません。必要に応じて対象ウィンドウに文字入力できることを手動で確認します。

候補取得はCore Graphicsのアプリ情報とAccessibilityの標準ウィンドウを組み合わせます。AXに対応しないウィンドウやAPIから見えないウィンドウが欠落する場合があります。別Space、フルスクリーン、最小化、非表示を含む全ウィンドウの完全な列挙は保証しません。

このアプリは画面収録権限を要求しません。診断ログにはPIDやウィンドウタイトルが含まれる場合があるため、共有前に確認してください。
